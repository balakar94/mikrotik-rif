# Fuzz harness (`fuzz/`)

`cargo-fuzz` targets for the `mikrotik_rif::parser` surface. The parser is the
only part of the crate that accepts attacker-influenced bytes (a capture file
that left the router), so it is the part worth fuzzing.

This is a **separate crate** (`mikrotik-rif-fuzz`) with its own workspace and
lockfile. It is excluded from the shipped package through the parent manifest
(`exclude = ["/fuzz"]`), and `fuzz/target/` plus `fuzz/Cargo.lock` are already
in `.gitignore`.

## What is asserted

Only **no panic / no hang**. Every `RifError` is an expected outcome and is
ignored; nothing semantic is asserted about returned data. The `parse_capture`
and `scan_container` targets use deliberately **tiny `CaptureLimits`** (parts 4,
span 256, part 256, total 1024, line 256) so budget checks trip immediately and
the fuzzer spends its budget on error paths instead of large allocations.
`expand_payload` caps decompressed output at 4 KiB for the same reason.

## Targets

| Target | Surface under test |
| --- | --- |
| `parse_capture` | `Capture::from_bytes`, then `read_bytes` + `read` for every readable part |
| `unpack_body` | `codec::unpack_capped` (input-derived budget) and `codec::unpack` |
| `scan_container` | `scanner::locate_parts` with a fresh notes buffer |
| `expand_payload` | `deflate::expand` with a 4 KiB output limit |

## Toolchain

`cargo fuzz` needs a **nightly** toolchain: it adds `-Zsanitizer=address` and
the sanitizer-coverage pass flags, which stable rustc rejects. The repository
pins **stable 1.95** in `rust-toolchain.toml`, so run the nightly override
explicitly with `cargo +nightly`.

```sh
rustup toolchain install nightly
cargo install cargo-fuzz
```

A plain `cargo check`/`cargo build` of this crate *does* succeed on stable
(libFuzzer's bundled runtime provides `main`), but the resulting binaries are
not coverage-instrumented: libFuzzer prints `no interesting inputs were found
so far. Is the code instrumented for coverage?` and cannot discover new paths.
Use `cargo +nightly fuzz` for real campaigns.

## Running

```sh
# Index + expand, capped input length so corpus files stay small.
cargo +nightly fuzz run parse_capture -- -max_len=65536

# The other targets (add -max_len=65536 to unpack_body as well).
cargo +nightly fuzz run unpack_body
cargo +nightly fuzz run scan_container
cargo +nightly fuzz run expand_payload
```

Useful variants:

```sh
cargo +nightly fuzz list                       # list targets
cargo +nightly fuzz run parse_capture fuzz/corpus/parse_capture   # explicit corpus
cargo +nightly fuzz cmin parse_capture         # minimise the corpus
RUST_BACKTRACE=1 cargo +nightly fuzz run parse_capture
```

`scan_container`, `unpack_body` and `expand_payload` can replay the
`parse_capture` seeds with an explicit corpus argument, as shown above.

## Seed corpus

Seeds live in `fuzz/corpus/parse_capture/` and are tiny (30–144 bytes, all
under 1 KiB). They are generated by `fuzz/gen_corpus.py`, which re-implements
the non-standard, little-endian 24-bit envelope transcode from
`src/parser/codec.rs` (standard base64 would be wrong) and zlib-compresses the
payloads:

```sh
python3 fuzz/gen_corpus.py
```

| Seed | Intent |
| --- | --- |
| `valid_one_part` | one well-formed, readable part (`export` → `hello\n`) |
| `empty` | zero-byte file |
| `stray_close` | closing marker with no open (scanner note) |
| `unterminated` | opening marker without a close (`UnterminatedPart`) |
| `nested_open` | second open before the first closes (first part dropped) |
| `damaged_body` | valid envelope, payload is not zlib (`Deflate` on read) |
| `lossy_label` | non-UTF-8 label (lossy-label path) |

libFuzzer skips zero-byte corpus files, so `empty` is exercised by the
`verify_corpus` smoke test rather than by corpus replay (the fuzzer still
generates empty inputs on its own).

Because the generator is Python and the parser is Rust, a smoke test keeps them
from drifting:

```sh
cargo run --manifest-path fuzz/Cargo.toml --example verify_corpus
```

It indexes every seed through the real parser and asserts the outcome listed
above; it prints `all 7 seeds behave as documented` on success.

## CI intent (non-blocking)

Fuzzing should not gate pull requests: a nightly toolchain plus a meaningful
campaign is too slow and too flaky for the PR path. The intended shape is a
**scheduled or manually dispatched** job that builds the harness, runs each
target time-boxed (for example `-- -max_total_time=300 -max_len=65536`), and
uploads any crash artifact (`fuzz/artifacts/<target>/`). The committed seed
corpus and `verify_corpus` example are the fast, PR-safe layer. No workflow
files are modified by this harness.

## Findings

A crash artifact is written to `fuzz/artifacts/<target>/`. Reproduce it with:

```sh
cargo +nightly fuzz run <target> fuzz/artifacts/<target>/<artifact>
```

Treat any panic, assertion, integer overflow (the targets are built with debug
assertions under `cargo fuzz`) or hang as a parser finding; route fixes for
`src/parser/*` to the owning stream. The `#![forbid(unsafe_code)]` in the parent
crate does not apply to `libfuzzer-sys`, which compiles C++.
